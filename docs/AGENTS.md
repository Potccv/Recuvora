# 设计文档维护规范

继承 [项目规范](../AGENTS.md)。导航见 [README](README.md)，共同设计为 [架构](architecture.md)、[审批与受限修复](approval.md) 及 [插件契约](plugins.md)。

- 分清设计目标、实际实现、验证范围和待定事项，不提供不存在的程序命令或可执行配置。
- 框架、业务与装配分别说明；源码分组、插件包、运行实例及工作进程不默认一一对应。
- 内置同进程模块、隔离提供方、独立安装扩展的来源与升级能力分别陈述；不把静态选择写成独立热安装。
- Recuvora 不提供节点程序；节点与第三方宿主侧业务插件由独立项目发布。新业务可由插件带入契约/schema、消费与验证逻辑，宿主侧是逻辑角色而非同进程要求。当前已实现 JSONL v1 节点接入与只读第三方契约注册/消费，按 extension-protocol.md 陈述限制；不可写成通用写授权、任意热安装或已验证跨机部署。
- 本地契约与远程代理语义保持一致，同时明确跨进程的取消、断连与未知结果；不要求本地调用一律 RPC。
- 依赖变化、清理和升级需检查在途任务、权威服务与外部副作用；effect 撤销不能写成业务回滚保证。
- 授权、持久恢复、源码修改范围和平台会话变化同时检查架构、插件设计及局部规范，禁止残留冲突描述。
- 区分提供方原生工具或审批、宿主注册的动态工具路由和 Recuvora 业务授权；记录同一 Harness 的执行/审批角色隔离及失败行为，不把模型评估写成任意授权。
- 当前受限文本替换与模拟分别表述；宿主文档只记录当前能力和自动验证边界，不保留按日期排列的真实环境或跨项目验收流水，也不把文件读回一致写成目标业务恢复成功。
- 文档示例只使用抽象 target/workload、provider observation 和 external action；具体产品、对象类别、实例名、业务字段、故障样本、供应商私有事实和活动部署归对应集成项目维护。
- 共同规则放在共享设计，模块通过相对链接引用，不复制整套规范。
- 引用外部项目时给出官方来源并说明借鉴范围；不声明未实现的第三方包或 API 兼容性。
- 新增文档登记导航，改名同步引用；检查目录树、链接、代码围栏和设计示例的一致性。
- 文档校验只证明文档与路径状态，不替代程序测试、平台支持或长期稳定性证据。
