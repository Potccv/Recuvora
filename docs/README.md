# 项目设计文档

本目录维护跨模块的架构、组合与可靠性依据。**已落地最小框架、模拟任务原型、多 Harness registry、通用外部节点代理，以及带持久审批的受限文本修复 CLI。** 当前真实动作只覆盖白名单既有 UTF-8 文件的有界全文替换；另已实现 JSONL 外部节点 Harness 代理、受限只读第三方插件注册/消费与官方控制台 HTTP API。具体 Harness 提供方由独立节点项目维护；其他本机平台执行后端、目标专属外部动作、自动节点恢复及完整自愈架构仍在规划。当前可运行范围以[项目 README](../README.md)及各模块文档为准。

## 维护边界

- 共同规则在本目录定义，局部 README 维护职责、契约、运行模式和限制，并引用共同依据。
- 框架机制、业务服务、源码组织、包发布与进程边界分别描述；同一能力可以有本地实现与隔离代理。
- 明确内置模块随宿主更新，独立扩展按协议安装；不得把配置启用或源码模块写成动态代码加载。
- 节点程序由外部项目提供；第三方宿主侧插件可以补齐新业务契约和消费逻辑。宿主维护通用机制、节点通信及开发约束；单 Cargo 包不是外部扩展的构建限制。
- 注册清理与外部动作恢复分别描述，持久事实与瞬时事件分别定义。
- 尚未选择的存储、编码、格式和支持矩阵保留待定，示例不得伪装成已实现接口。
- 目录调整核验分层导航与局部规则，协议或运行边界变化同时检查两份共享设计和受影响模块。
