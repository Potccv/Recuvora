# 部署组合模板规范

继承 [项目规范](../AGENTS.md)；目录职责见 [README](README.md)，装配实现归属 [boot](../src/boot/README.md)。

## 模板内容

- 部署 profile 只描述组合，不实现业务流程或代替插件安装校验。`repair` 配置另含本机操作员显式提供的审批委托；该政策须由可信授权服务逐操作核验，不能因模块已启用便获得执行权限。
- profile 描述宿主配置、插件实例与外部节点绑定，不提供节点启动角色、节点包构建或发行组合。节点由独立项目构建发布，即使与宿主部署在同机也保持独立产品边界。
- 明确宿主组合、服务实现、版本约束、依赖作用域和运行边界；部署位置不等于能力目录或强制独立进程。
- 选择内置实现时仅引用已编入宿主的代码；不得声称配置可安装任意 Rust 模块。
- 第三方宿主侧插件可独立增加命名空间、版本化业务契约和消费逻辑，默认进程外；不为常规新增业务要求核心重新编译。模板只声明依赖与绑定，不能代替插件包或 loader，遵循 [插件设计](../docs/plugins.md)。
- 多个可信能力共用工作进程时说明共同故障范围、资源限制与会话要求。
- 区分宿主启动的插件工作进程与独立节点自行监督的本机进程；不能把远端断连等同回收完成。
- 授权和持久服务的权威提供者必须明确；关键服务缺失或恢复未完成时相关执行保持关闭。
- 外部节点绑定说明授权来源和执行前校验，不能以离线或同机部署绕过业务授权。契约注册不授予权限，必需插件缺失或版本不兼容时停用相关能力，不以插件私有裁决或日志替代可信授权与权威记录。

## 维护与验证

- 模板仅使用占位值，不提交真实凭据、运行数据库、安装包或环境专属绝对路径。
- 模板只使用无业务含义的 target/workload/provider observation 占位值；不得出现具体受监控产品、对象类别、实例名、业务字段、故障样本、活动部署或真实环境验收数据。
- 配置格式和加载器未实现前只维护设计，不新增看似可运行的伪配置或启动命令。
- 当前有 Harness、repair、ExtensionsConfig、MonitorsConfig 和控制台配置加载器；只描述真实字段与已有入口，不把 SSH 命令传输写成内置节点程序，不把只读插件注册写成通用副作用授权或安装市场。
- 验证依赖、作用域冲突、角色组合、共享故障和平台能力不可用时的降级行为。
- 配置变更区分排空、重启与宿主升级；模板不能承诺关键业务任意热替换。
- 运行时修复 AI 不得修改本目录对应的启用配置；维护变更应更新职责、限制和验证状态。
