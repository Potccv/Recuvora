# 源码模块开发规范

继承 [项目规范](../AGENTS.md)。能力导航见 [README](README.md)，共同机制见 [插件设计](../docs/plugins.md)。

- 使用项目根唯一的 Cargo package；在 `src/` 内按能力组织服务契约、实现与领域消费者，不逐能力拆 Cargo 包。
- 该限制只针对宿主。外部节点及第三方业务插件独立构建发布；不在本项目增加节点可执行程序或节点构建 feature。nodes 仅实现宿主侧接入、管理及事实核对。
- framework 维护通用插件机制，recovery 维护自愈业务，boot 选择部署组合；禁止将三者重新合并为一个硬编码入口。
- monitors 负责宿主只读观测、规则、时效和覆盖，复用 nodes 的契约路由；recovery::incidents 负责检查点与故障权威存储。未知、过期及确认收到不能作为条件解除或业务恢复事实。
- server 只把可信服务映射为版本化 HTTP API、认证、持久传输回执与日志；interfaces 维护官方共享页面和单一 API 客户端。Web/Desktop 不复制权威状态机，断线或取消不得自动重放副作用。
- 正式审批与受限修复位于 recovery 的独立模块，actions 负责白名单文本执行边界；模拟引擎保持封闭，模拟授权布尔值不能授予真实动作权限。
- 执行和审批允许选择同一 Harness 实例，但会话、工具权限及并发容量分别管理；审批评估只能经可信授权服务核验后变为一次执行许可，遵循 [审批说明](../docs/approval.md)。
- `lib.rs` 声明模块，`main.rs` 保持薄启动入口；能力模块以 `mod.rs` 及其子模块组织实现，不再嵌套 `runtime/src`、`engine/src` 或 `cli/src` 这样的子包目录。
- 源码层、能力目录和平台子目录维护 README.md 与 AGENTS.md，说明提供与依赖的服务、事件、配置、运行边界、更新方式和验证状态。
- 依赖和目标统一登记在项目根 `Cargo.toml`；`src/` 不包含子 manifest，全部测试代码放在项目 `tests/`，不把测试数据或构建产物写入源码树。
- 区分随宿主发布的内置模块、独立安装的进程外扩展、契约模块和装配模块；目录存在不能证明加载能力已实现。
- 内置实现以配置选择已经编入的代码；不得用 Cargo feature 或静态注册冒充外部包动态安装。
- 服务调用依赖契约；远程提供方通过协议代理接入相同能力体系，保留调用失败与未知结果语义。
- 外部新业务允许宿主侧插件注册命名空间与版本化契约/schema，并提供消费、流程和验证逻辑；不把所有新领域硬编码进核心。通用兼容、权限、限额和权威记录边界保持有效，具体接入约束见 [插件设计](../docs/plugins.md)。
- 记录依赖版本及所属作用域；必需服务缺失时停用依赖者，不能回退到不校验授权或不记录执行事实的路径。
- 注册、订阅、任务和资源均有实例所有者与清理方式；局部清理不是回滚已发生的外部操作。
- 本地可信模块共享宿主故障与权限范围；外部、原生或复杂运行时明确隔离进程及共同故障范围，不要求每个服务单独进程。
- 新增代码不得依赖真实凭据或开发者当前活动目标；示例和材料标明设计或可运行状态。
- 源码模块文档、示例和测试说明只使用抽象 target/workload、provider observation 和 external action；不得记录具体受监控产品、对象类别、实例、业务字段、故障样本、活动部署或跨项目真实环境验收。
