# 启动与装配开发规范

继承 [源码模块规范](../AGENTS.md) 与 [项目规范](../../AGENTS.md)；职责见 [README](README.md)，模板范围见 [profiles](../../profiles/README.md)。

## 组合与启动

- 保持统一薄入口，业务循环和任务状态机留在 recovery，实际能力留在所属领域。
- 只装配宿主、宿主侧插件和外部节点绑定，不提供节点启动角色、节点程序或节点发行构建；独立节点项目负责自身依赖和本机进程。
- `recuvora-desktop` 保持仅创建窗口并加载 `src/interfaces/ui/public/` 共享资产的薄入口；不在 Desktop 启动层实现 UI 专属业务、授权裁决或演示数据。Web 静态产物不需要第二套 Rust 启动入口。
- `desktop-ui` 只控制 Tauri 编译依赖与桌面二进制，`web-ui` 只标识共享前端能力；feature 选择不意味着运行时 API、业务动作或目标平台能力可用。
- 装配时明确角色、作用域、提供方版本、必需依赖及本地或进程外运行边界。
- 初始化顺序由依赖决定；必需授权、持久记录与恢复检查完成前不能开放执行派发。
- 拒绝未知提供方、依赖循环、作用域冲突与不兼容版本，不依靠注册顺序选择权威实现。
- 部署 profile 只决定组合，不产生任务授权，也不因为默认启用而跳过插件和权限校验。`repair` 的显式委托政策交由 recovery 逐操作核验，启动层不自行批准。
- 内置模块只选择已编入实现；新增内置代码需要更新宿主，不能包装成任意插件热加载。
- 未来新增业务契约与消费逻辑可由第三方宿主侧插件独立提供，默认进程外；不把宿主侧误解为必须与核心同编译。校验命名空间、契约版本、依赖及权限，缺失插件时停用相关能力，遵循 [插件设计](../../docs/plugins.md)。

## 变更与验证

- 配置变更、工作进程重启和宿主升级分别处理，明确在途操作与失败恢复策略。
- 区分宿主启动的本地插件进程与独立节点自行监督的远端进程；连接中断不能作为远端停止或回收完成的依据。
- 部分启动失败要清理已创建资源；关闭先阻止新派发，再处理在途调用，清理不代替副作用核验。
- 验证缺失关键服务、恢复未完成、初始化中断与关闭超时，相关执行始终有明确阻断原因。
- 不在启动入口嵌入真实凭据、目标专属规则或环境专属绝对路径。
- Desktop 与 Web 必须加载同一前端源并保持相同页面和功能表述；载体差异限于窗口/浏览器环境标识。构建与打包输出必须由脚本导向项目外目录。
- `demo`/`inspect` 只运行封闭模拟场景；`harness` 显式加载已实现的局部 Harness 配置并调用受限服务，不作为完整部署 profile 或安装入口。

## 当前实现约束

- 装配只注册通用 `remote-node` 工厂；远端节点失败不得回退到未配置的本机提供方，也不得把供应商实现隐式加入 server/UI。

- 只负责参数、装配与结果展示，不创建第二套任务状态机。
- 真实 Harness、扩展注册表与监控服务统一经过 host::HostRuntime 的框架服务及生命周期装配；配置加载置于共享 configuration 层，HTTP 不借用 CLI 实现。新入口复用该层，关闭先同步撤销派发、再等待原调用收尾并检查关闭报告，不能只丢弃注册表 Arc。
- 已有可信外部程序注册、JSONL 节点代理与可选 HTTP 服务；节点安装和构建属于独立项目，宿主不提供节点角色。未知安装市场、签名分发和自动升级不得写成实现。
- Desktop 保持无业务 command 的薄壳，Web/Desktop 共用 HTTP 客户端；server feature 提供可信 API，未连接与显式演示状态不得伪造权威数据或产生操作。
- 通过框架声明和解析模拟任务服务；引擎恢复完成前不发布服务，停用时优雅关闭引擎。
- 模拟场景不增加命令、网络、文件修复或桌面输入能力。
- 参数和运行错误返回明确非零退出码；预期模拟失败应按任务状态展示。
- 故障注入二进制保留在集中测试目录，不能作为产品隐藏入口。
- 活动 Harness 配置必须位于源码目录外；结构校验、实例选择和提供方装配错误不得静默回退。列表区分本地装配条件与实际登录/运行状态。
- Ctrl-C 请求协作取消后等待提供方完成清理与结果返回；Unknown 保留已知关联信息，不自动重新创建项目或会话。
- `repair` 只装配已实现的审批和文本动作。委托政策与状态不向模型提供写权限；管理记录不依赖目标仍存在，批准不隐式执行，Unknown 不得转为普通失败或自动重试。
