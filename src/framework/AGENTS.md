# 插件框架开发规范

继承 [源码模块规范](../AGENTS.md) 与 [项目规范](../../AGENTS.md)；职责见 [README](README.md)，机制见 [插件设计](../../docs/plugins.md)。

## 通用机制

- 框架只维护上下文、服务、依赖、事件、实例和生命周期，不导入自愈、目标专属或供应商私有业务。
- 服务版本、作用域和提供者必须明确；同一作用域内的权威提供者冲突不可用注册顺序静默解决。
- 必需依赖缺失时停用依赖者，依赖变化采用可观测的重新绑定，不默默绕过依赖检查。
- 区分源码包、运行实例、服务和工作进程，不用同一标识替代；本地服务调用不强制序列化。
- 远程后端暴露延迟、超时、取消、断连和未知结果，不把所有调用失败都标成可安全重试。
- 静态注册与配置选择不等于独立安装；新增内置代码需要更新宿主。
- 为第三方宿主侧插件规划可独立注册的命名空间、版本化业务契约、依赖、能力、事件和受控路由；不要求每种新业务预先编入宿主核心。宿主侧是逻辑角色，独立安装的插件默认进程外，不等于 DLL 或静态内置模块。
- 契约或 schema 注册不产生权限；插件消费逻辑必须使用宿主可信授权与权威记录，不能自行建立替代裁决。所需插件缺失或契约不兼容时停用相关能力。
- 独立节点由外部项目构建发布；本框架不实现节点程序或节点发行构建，共同边界遵循 [插件设计](../../docs/plugins.md)。

## 生命周期与验证

- 每项订阅、注册、定时器和后台任务都有实例所有者、容量限制及清理责任。
- 停用先禁止新派发、处理在途调用，再撤销注册与清理；资源清理不声称回滚外部副作用。
- 宿主侧监督后端负责宿主启动的本地插件工作进程；独立节点自行监督其本机工作进程。框架和节点代理不得仅凭连接关闭宣布远端进程树已停止操作或回收完成。
- 覆盖依赖循环、作用域冲突、服务失效、取消竞态及反复启停的资源增长。
- 先验证最小契约与可控实现切换，再扩充加载功能；不承诺任意热替换或对恶意同进程代码的沙箱隔离。

## 当前实现约束

- 保持框架通用，不引入任务状态、授权、Harness、平台或供应商规则。
- 类型化宿主内运行库不直接承担第三方加载和节点协议；现有外部注册与路由由 nodes/protocol 实现，并通过 boot::host 装配到运行库。不把契约接入写成完整安装包管理或任意动态安装，不编造插件市场或节点启动角色；状态引用 docs/implementation-status.md。
- 通用取消与在途调用作用域不得依赖 Harness 等领域类型；关闭同步撤销派发，监督等待原 future 完成，调用者丢弃 future 不得提前释放在途所有权。结果未知的语义保留在提供方与所属业务契约。
- 作用域按完整字符串匹配；扩展版本协商、层级作用域或热替换时须同时明确契约和迁移规则，不能静默改变现有解析行为。
- 任一生命周期 await 前把清理责任保存在运行时中；取消启动或停机 future 后仍可显式继续停机。
- 取消请求不等于任务已结束。等待所属后台任务回收后再运行 disposer；无法确认回收时保留待清理资源，不返回虚假的干净状态。
- 停止钩子不得从已关闭的上下文发起新工作；领域服务自身负责旧句柄的派发关闭与在途排空。
- 不以 timeout 或 panic 捕获宣称宿主内模块具有进程隔离能力；钩子和 disposer 均位于可信、合作式边界。
- 测试统一维护在 [tests/framework.rs](../../tests/framework.rs)，测试由项目根 Cargo 包统一发现；不在 `src/` 下新建分散测试文件。
