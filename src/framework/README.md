# 插件框架

本模块维护通用 Rust 插件框架，以服务契约、依赖、事件和生命周期组合能力。

**当前状态：已实现 [crate::framework](#运行库实现) 可信宿主内运行库，包含类型化服务、启动前依赖校验、合作式启停、有界事件与实例资源清理。真实 Harness 与扩展注册表通过 [boot::host](../boot/host.rs) 复用该运行库；跨进程注册及远程代理由 [nodes](../nodes/README.md) 与 [protocol](../protocol/README.md) 实现。完整依赖重绑定、安装包管理与任意热替换尚未实现。** 实现与验收边界统一见 [实现状态](../../docs/implementation-status.md)。

## 职责

- 提供上下文、作用域、服务注册与解析、必需和可选依赖声明。
- 管理插件实例的装配、启停、依赖变化、事件订阅及受控资源清理。
- 定义本地提供方与远程代理接入的运行后端接口，保留能力契约语义。
- 为配置选择已有内置实现、外部插件接入及生命周期观测提供统一机制。
- 规划第三方宿主侧插件注册命名空间、版本化业务契约、依赖、能力、事件与消费逻辑，通过受控路由接入外部节点；新增业务通常不要求重新编译宿主核心。

## 接口与边界

框架不包含任务修复、授权策略、目标专属规则或模型提供方私有业务；这些由所属领域提供。服务标识、实例标识与工作进程标识分别维护，一个工作进程可以承载多个可信能力。

本地可信模块与宿主共同编译发布；配置只能选择已编入的实现。独立安装的扩展默认通过进程外后端接入，不以 Rust 原生动态库作为通用加载方式。

“宿主侧插件”表示提供宿主所消费的业务契约和逻辑这一角色，不表示插件必须与宿主同进程或共同编译。独立节点是各自构建发布的外部产品；框架负责插件组合与宿主侧服务接入，不提供节点程序或节点构建目标。第三方契约注册只扩展可识别的数据与服务，不授予操作权限，也不能通过契约注册自行替换或绕过可信授权和权威执行记录服务；缺失对应插件或契约不兼容时停用相关能力。共同边界见 [插件设计](../../docs/plugins.md)。

[业务服务](../recovery/README.md) 使用框架提供契约实现；[启动装配](../boot/README.md) 选择宿主与插件组合；[节点管理](../nodes/README.md) 维护宿主侧节点身份、连接与能力绑定；[通信协议](../protocol/README.md) 支持跨进程和跨节点代理。宿主启动的本地插件工作进程由宿主侧监督后端负责；独立节点自行监督其本机工作进程。连接关闭不能证明远端进程已停止或副作用已结束。

订阅、定时器、服务注册等资源应登记到所属实例，停用时停止新派发、处理在途调用并清理。effect/dispose 不撤销已经生效的外部动作，也不能证明旧执行者已失去操作能力。

## 计划验证

[运行库测试](../../tests/framework.rs) 已覆盖同进程依赖顺序、服务冲突与缺失、循环、类型和作用域、启停失败与超时、事件过载、资源回收顺序、取消后继续清理和两种已编译提供方的选择。测试由项目根 Cargo 包统一发现，使用 `cargo test --test framework` 执行。

后续平台与扩展验证仍包括：

- 验证作用域内提供者冲突、依赖缺失、循环依赖、实现切换及依赖者可控启停。
- 验证实例卸载、订阅与资源清理、在途调用排空，以及长时间重启后的资源增长。
- 验证远程代理断连、取消与未知结果，防止本地和远程后端产生不同业务解释。
- 验证第三方契约命名空间与版本冲突、缺失插件时相关能力停用，以及契约注册不能绕过宿主授权和执行记录。

具体注册 API、短暂事件形式和当前限制见 [运行库说明](#运行库实现)；通用可替换运行后端接口尚未实现，已有进程监督保留在协议与提供方层。共同规则见 [插件设计](../../docs/plugins.md)，本域规范见 [AGENTS.md](AGENTS.md)。

## 运行库实现

可信宿主内模块的最小运行库，提供服务装配、依赖校验、合作式启停、短暂事件和实例资源管理。源码入口为 [mod.rs](mod.rs)，不包含任务恢复、Harness、目标平台或进程监督业务。

### 已实现接口

- `InstanceId` 标识一次装配中的模块实例；`ModuleMetadata` 声明该实例提供和必需的服务。
- `ServiceKey` 由名称、主版本和作用域字符串组成，三者完全相同才匹配。作用域是单层命名空间，不做父子继承、默认回退或通配匹配；主版本不做区间协商。
- `ModuleContext::publish` 注册类型化 `Arc<T>`；`service::<T>` 只解析声明的依赖及自身服务，并核对 Rust 类型。trait 对象可以通过领域契约中的有尺寸包装类型承载。
- `Runtime::validate` 在调用任何生命周期前检查提供者冲突、缺失依赖及循环；`start` 按拓扑顺序启动，并确认提供方已发布所有声明服务。
- 任一启动失败或超时，先停止部分初始化的当前实例，再逆序停止已启动依赖。未启动的模块不会收到停止钩子。
- `shutdown` 在调用停止钩子前拒绝该实例的新注册、解析、订阅、事件派发及后台任务，然后逆序收尾。停止失败通过 `ShutdownReport` 返回，不跳过可以继续进行的清理。
- 实例拥有的后台任务先收到取消请求，框架等待其 future 结束，再逆序执行同步 disposer。订阅、服务注册随实例清理。`snapshot` 显示仍在运行或等待清理的资源数量。

一个 `Runtime` 只执行一次启动和停机周期，停机可重复调用。内置实现切换通过重新创建运行时并选择不同已编译模块完成；没有任意热替换、动态安装或 Rust 动态库加载。

### 生命周期与取消约定

`Cancellation` 是与业务无关的协作取消令牌。`CallScope` 为服务记录最多 1024 个在途调用：`close` 同步拒绝新派发并请求取消，`shutdown` 等待原 future 实际完成；调用方丢弃 future 时，监督任务继续等待提供方清理，不提前释放槽位。取消等待不会重新开放作用域，后续可继续等待收尾。`HarnessCancellation` 仅作为兼容名称重导出；协议和节点层直接依赖框架取消类型。

`CallScope` 只证明所属 future 结束，不能证明远端工作进程已退出或目标动作已撤销。提供方必须在返回前完成其监督与回执处理，未知副作用仍由业务保留为 Unknown；调用者仍需继续等待原请求以接收完整结果。真实宿主显式关闭先同步撤销所有注册表入口，再排空 Harness 和扩展，最后逆序撤销框架服务；排空超时保持运行时所有权并返回错误。

`Module::start`、`stop` 返回 `LifecycleFuture`，预期错误用 `ModuleError`。钩子必须合作式让出执行权、允许 future 被取消，并使停止能够处理部分启动。调用者取消停止钩子后重试 `shutdown` 可能再次调用该钩子，因此停止逻辑须幂等。

停止钩子收到的上下文已经关闭新工作。需要排空的服务句柄应在启动时保存到模块中，停止时使用已保存句柄完成业务自己的关闭和排空。框架不能撤销消费者已经获得的 `Arc`，也不能为任意服务自动阻止调用；服务契约仍需实现自己的接受工作开关与在途调用管理。

框架将待回收任务和 disposer 保存在运行时中，取消 `shutdown` future 不会丢失它们。任务回收超时时返回 `LifecycleTimeout`，保留待清理实例及其尚未停机的依赖，`snapshot.pending_cleanup_instances` 和资源计数继续反映未完成清理。再次调用 `shutdown` 可继续收尾；在旧任务实际结束之前不会执行该实例的 disposer。

`Runtime::drop` 会撤销新工作并请求取消后台任务；若当前仍有 Tokio 运行时，会调度尽力回收。Drop 无法调用异步停止钩子，也不保证进程退出或 Tokio 关闭时完成清理。需要确认收尾结果的调用方必须显式 `shutdown().await` 并检查报告。

同进程可信模块共享宿主故障边界。超时依赖 future 合作式调度，不能抢占阻塞代码、死锁、任意 panic 或进程终止；同步 disposer 必须快速返回，框架不对其施加强行中断。需要强隔离的工作使用进程外后端，监督责任归属实际启动该进程的宿主或独立节点；目前协议实现有界传输和直接子进程监督，远端进程树回收仍依赖节点及其证据。资源清理不撤销外部业务副作用。

### 事件与容量

`subscribe(topic, capacity)` 创建有界事件队列，`emit` 使用非阻塞投递，返回成功、队列已满及已关闭接收方计数。满队列丢弃本次事件，不阻塞发送者；`Event` 是有大小上限的主题和文本负载。事件不持久化，不作为业务恢复事实或授权依据。停机关闭所属订阅，但接收者仍可能读到此前已入队的事件，应自行核验当前业务状态。

默认限额由 `LifecycleOptions` 设置：最多 64 个实例，每实例 128 项后台任务或 disposer、64 项订阅，每订阅最多 256 条队列项，每事件合计最多 64 KiB。启动与停止钩子各有 5 秒时限，后台任务收尾有 2 秒时限。完成的后台任务句柄仍占用该实例本周期资源额度，直至停机回收；该接口面向少量长期后台任务，不是无限次短任务调度器。
