# Recuvora 共享用户界面

本目录保存 Web 与桌面壳共同使用的静态单页界面。`public/` 是零第三方前端依赖的 HTML、CSS 和 JavaScript ES modules，可由 Web 服务或桌面 WebView 原样托管；两种承载方式不维护不同的业务页面。

## 官方界面范围

官方 UI 基础壳承担完整标准控制台的展示职责，既包含导航、连接、能力管理和设置，也包含监控与故障、Harness 会话、修复详情、审批、日志查询及模拟实验室。标准业务页面随官方 UI 交付，不要求单独安装 UI 插件。

页面依赖统一的版本化服务契约，后台提供方可以是内置业务模块、宿主侧插件或独立外部节点。提供方可替换不意味着页面需要拆成插件；提供方缺失时，官方页面应准确显示未配置或不可用。前端只呈现权威视图并提交请求，不复制审批规则、执行逻辑或持久状态机。插件可登记官方尚未覆盖的声明式只读监控专页；页面仍由官方 UI 解释和安全渲染，不加载插件 HTML、JavaScript、样式或外部资源。

Web 与 Desktop 保持共用资产和可选交付。宿主可以无 UI 运行，关闭界面不应停止后台任务或节点连接；官方标准业务页面不构成宿主核心的运行依赖。

## 当前状态

当前界面已接入 [可信 HTTP 服务](../../server/README.md) 的 `/api/v1` 契约。默认真实模式先显示独立认证页；提供服务地址和访问密码 / Bearer 令牌并通过宿主验证后，才显示业务导航与运行记录。认证成功返回原先请求的页面，失败不生成业务数据；401 认证失效清除身份范围内的数据并回到认证页。`public/data.js` 只在操作员显式进入演示模式后使用，该模式所有提交入口保持禁用。运行壳持续显示连接模式、读取时间和陈旧状态。

界面覆盖以下入口：

- 概览、受限修复任务与操作审批；
- 按目标归组的监控状态、最近样本详情、分页故障记录及人工确认收到；
- 宿主统一监控中心中的插件目录，以及每插件独立的声明式只读监控专页；
- 目标提供方的独立观测记录页、增量记录流和按配置分类的错误记录双栏；
- Harness 实例、原生项目和文本轮次；
- 按来源、级别、任务、操作和文本筛选的有界日志分页；
- 与真实操作隔离的模拟实验室；
- 当前能力和规划能力的准确状态，实现阶段与运行可用性分别筛选；
- 共享界面设置、构建承载方式和项目限制。

运行时能力和外部扩展连接状态均来自服务快照；未配置、不可用和已连接分别展示。监控与故障页面读取宿主采样和持久故障契约，不在前端运行探针、归并故障或裁决健康状态。新增领域扩展不自动获得文件写入权限，通知、视觉、桌面交互和业务验证不因页面存在而实现。当前真实能力边界仍以项目根 README、审批说明和各能力目录文档为准。

## 文件

```text
mod.rs              # Rust 侧共享 UI 资源模块
public/
├── index.html       # CSP、挂载点和模块入口
├── styles.css       # 响应式深色设计系统
├── data.js          # 明确标记的演示数据
├── shell.js         # Web/Desktop 的薄壳环境适配
├── app.js           # 路由、业务页面与操作交互
├── api.js           # 唯一 HTTP 客户端、取消、串行快照读取与未知结果
├── dom.js           # 无业务状态的安全 DOM 与展示组件
├── history.js       # 当前摘要页、游标、有限详情缓存与失效
├── monitoring.js    # 目标归组、监控维度、故障分页/详情与确认收到交互
├── plugin-monitoring.js # 插件监控声明的严格校验、安全投影与纯文本表格
├── project-logs.js  # 独立有界观测记录流、错误记录流与读取生命周期
├── refresh.js       # 保留控件、焦点及展开状态的区域 DOM 协调
├── favicon.svg      # 浏览器矢量图标
└── favicon.ico      # Desktop 打包所需的同款 Windows 图标
```

ES modules 应通过 HTTP 或 WebView 资源协议加载，不保证直接以 `file:` 打开。Web 可与 `recuvora serve` 同源托管；Desktop 在连接设置中指定同一服务。桌面壳不注册业务 command，不能形成第二套审批或执行接口。

## 连接与操作语义

- 服务地址只接受 HTTPS 或本机回环 HTTP 根地址，拒绝 URL 内嵌凭据、路径及查询参数；令牌只留在客户端实例内存，断开、切换演示和关闭页面时清除，不写浏览器持久存储。
- 每次请求使用 Bearer 认证，禁止跟随重定向、携带 Cookie 或缓存响应；响应读取上限为 4 MiB，默认超时 12 秒。
- 快照默认每 5 秒持续串行读取，无并发重叠，没有固定 120 轮停止限制；每次响应、超时与缓存容量仍有界。失败以最多 30 秒间隔退避，页面隐藏或连接切换时取消；重新显示后恢复。认证失败需要操作员处理，401 清除旧身份数据并回到认证页；短暂请求失败保留上次快照并标明陈旧。
- 初始化只读每类历史的首批摘要；完整模型回复、文件差异和政策按需读取。历史按不可变 ID 降序分页，每页 25 条；筛选与翻页不会被后台轮询覆盖。审批默认独立查询需处理队列，全局数量来自服务计数，不受近期已结束记录数量影响。
- 同一页面协调更新状态与计数，保留导航、编辑控件、焦点与证据展开状态；持久列表和观测记录区域由各自视图更新，不整页替换。页面内存最多保存 12 个页面的非密码草稿，切页返回恢复内容及字节验证，不写入浏览器持久存储。
- 详情缓存最多 8 条，本次操作回执最多 16 条；断开连接、切换身份或进入演示清空，并清除草稿。审批详情失效期间禁用旧动作，重新读取完整 revision 后依据动作清单恢复；新 revision 替换文件差异证据，保留理由供重新审查。
- Harness、修复和模拟提交先生成操作 ID；只发送一次 POST。202 表示服务接受，后续读取操作及业务记录确认结果；断连、超时或无法解析提交回执保留 Unknown 和操作 ID，不能自动重复提交。
- 操作回执只在对应提交或关联任务页面显示；宿主日志页以折叠区域集中查询全部操作记录，回执保留操作 ID、完整服务结果和提交关联供核验。
- 审批动作由服务返回的 `allowedActions`、当前权限和 revision 决定。提交前展示规范化完整操作、政策与理由；409 冲突触发重新读取，前端不能自行推进审批状态。
- 宿主日志查询只读取服务提供的有界页面，取消或失败不会伪装成空列表；结果显示本次查询读取时间。目标提供方观测记录由独立页面默认每 2 秒串行增量 GET 续读，窗口最多 2000 条普通记录、400 条错误记录与 2 MiB 文本；积压记录短间隔读取，失败退避，离开或隐藏页面取消。来源连续性变化和失效游标会明确停止并要求重新读取。`stream_label` 与 `available_streams` 只表示提供方定义的记录流，不暴露底层文件；错误流仅显示服务按显式 `error_levels`/`error_events` 分类的记录。当前来源与后端限制见 [控制台 API](../../../docs/console-api.md)。

## 监控与故障

配置自动发现时，监控列表还展示每个发现源的清单完整性、已登记与当前发现的目标数、最近接收和错误。即使尚无监控目标，也能看见发现失败或尚未确认完整的状态；展示本身不执行登记或生成健康结论。

“监控与故障”是官方标准页面，真实模式从 `bootstrap.monitoring` 或 `GET /api/v1/monitors` 读取摘要，单个监控详情通过 `GET /api/v1/monitors/{id}` 按需读取最近样本。健康状态、样本新鲜度、采集完整性和采样调度分别显示；调度运行中、无故障记录或缺少采样数据都不能解释为目标健康。未配置、无读取权限、采集错误和监控运行时错误分别提示。演示模式不填充此页面的真实监控或故障记录。

`bootstrap.monitoring.plugins` 提供插件监控目录摘要，目录只包含插件，不把节点实例当作插件页面。每个插件使用 `#/monitoring/plugins/{id}` 的宿主路由；首次进入只执行一次 `GET /api/v1/monitoring/plugins/{id}`，之后由操作员显式刷新。专属读取要求 `monitor.read` 与 `extension.read`，只使用固定 GET，不把插件登记的契约、方法或参数交给浏览器拼装。页面缓存最多 8 个插件；身份或权限变化、断开并重置连接、进入演示模式时清空，迟到响应通过连接代次和实例归属检查丢弃。

插件专属响应中的 `view` 是版本化声明，不是可执行页面。前端再次核验 32 KiB 总量、最多 8 个 section、总计最多 64 个 field、全局唯一字段 ID、非空字段集合、最多 16 段的合法 RFC 6901 pointer、固定 source/format 枚举、字符串 UTF-8 字节上限和 NUL 禁止规则；未知字段、类型、重复 ID 或任一越界会拒绝整份声明。允许的内容仅投影为宿主构造的纯文本事实表格，不接受 HTML、Markdown、URL、图片、脚本、样式、动作、class 或 tone。数值格式不会把超出 JavaScript 安全整数绝对值的 number、非安全整数时间戳或时长显示成精确事实；`json` 格式会递归执行同一数值范围检查，任一嵌套数值不安全时整格关闭失败。每个 section 按目标和已登记的 monitor `view_role` 匹配其 `monitor_role`；零个匹配显示未提供，多个匹配明确显示歧义，不选择其一或推断状态。服务端当前返回 `permission_denied` 或 HTTP 401/403 时立即丢弃此前缓存的插件声明与专属投影，不能以“陈旧内容”保留已经撤销的读取范围。

插件页固定同时显示注册/视图状态、按 `owner_plugin_id` 筛选的宿主权威监控三维状态与发现状态。声明缺失、登记无效、插件离线、响应无效或读取权限不足时，这些宿主标准内容仍作为降级页面存在。刷新失败可保留当前身份范围内上次成功的专属内容，但必须标为陈旧并显示读取时间；插件文本始终标注为只读展示，不能覆盖宿主健康、故障、授权、修复或业务恢复事实。未知的未来状态枚举显示为“状态未知”，不会借用成功颜色。

故障列表调用 `GET /api/v1/incidents`，默认 `status=active` 列出尚未解除的 open 和 acknowledged 记录，也可选择 resolved 或 all。每页最多读取 25 条，游标翻页保留当前筛选，初始化轮询不会把较早历史页替换成第一页。摘要不携带完整证据，`GET /api/v1/incidents/{id}` 才读取完整证据、revision 和确认记录。目标条件异常与采集异常分别展示；故障处理状态和当前观测条件也分别展示。

确认收到需要 `incident.read`、`incident.acknowledge` 权限以及完整详情返回的 `allowed_actions`。只有当前 open 记录且详情新鲜时启用，提交 `POST /api/v1/incidents/{id}/acknowledge`，正文仅含准确 revision 和可选 note，备注最多 4096 个 UTF-8 字节；操作员身份由宿主确定。该调用返回原子的持久故障记录，不创建通用执行操作，不批准或启动修复。

409 冲突会重新读取完整详情，旧 revision 按钮不能再次提交。确认回执丢失时保留 Unknown，只读取权威记录核验；没有自动重复 POST。后台刷新保留备注草稿，详情陈旧期间禁用确认。显式断开、身份切换或退出演示清除查询缓存和凭据；暂时离线保留陈旧视图并禁用提交，权限收回时清除对应证据缓存。

`acknowledged` 仅表示已知悉，不解除故障。`resolved` 只显示为“异常条件已解除”，不能表述为修复成功或业务恢复验证。

## 安全展示

审批详情默认展示带原文与替换行号的逐行变更，包括上下各三行相同内容；可切换查看两份完整文本。换行类型与末尾缺少换行独立标识，所有内容通过纯文本 DOM API 展示。差异算法先剥离相同前后缀，仅在最多 160,000 个单元的有界表中计算行对齐；超过预算按整段删除与新增展示。逐行预览最多 800 行，超出时提示使用完整文本，不裁剪完整审批证据。

共享样式提高正文、表格与状态的字号，审批决定理由位于正文区域，紧凑动作栏只显示当前状态与可用动作，窄屏不悬浮。认证使用独立入口布局；正常连接使用紧凑状态条，断线警告与演示模式分别显示。目标卡片保留健康、样本时效与采集完整性的独立维度；插件专属字段复用可横向滚动的语义表格，不接受插件样式；目标观测记录视图使用可滚动的普通记录与错误记录双栏，窄屏上下排列。

`tests/ui_diff.mjs` 随共享客户端行为入口执行，验证原文与提议文本的准确重建、重复行与换行差异、计算与渲染上限、恶意文本安全展示及完整文本切换。`tests/project_logs.mjs` 使用可控定时器验证目标观测记录的滚动读取、容量限制与生命周期，不连接具体提供方。

`dom.js` 通过 DOM API 和文本节点构造内容，业务页面共同使用这些组件，不使用 `innerHTML`。模型回复、路径、文件原文、替换文本、错误和其他外部字符串均作为不可信纯文本展示。前端不保存或推导授权，不把请求已发送显示成决定已接受，也不把 `Unknown` 显示成未执行或可安全重试。

行为测试位于 `tests/ui_client.mjs`，由集中 Rust UI 测试调用 Node.js 运行，使用模拟 HTTP 和最小 DOM，不启动外部模型或浏览器。覆盖模式切换、凭据范围、响应上限、游标分页与筛选保留、有限详情缓存、旧 revision 禁用、草稿保留、轮询取消、POST 不重试、Unknown 及不可信观测记录纯文本展示；监控用例另覆盖三维状态、故障按需证据、确认成功/冲突/回执未知、权限与断开清理，以及确认不解除条件和条件解除不等于恢复验证。插件监控用例覆盖仅 GET 的首次读取、插件目录与路由、节点排除、声明限额和未知字段拒绝、不可信文本安全展示、缺失/歧义投影、离线或无效响应时保留陈旧专属内容并继续展示宿主降级视图，以及权限变化后的缓存清除。`tests/server.rs` 验证大历史摘要、按需全文、游标遇到状态更新仍无遗漏，以及待审批不被已结束记录挤掉；目标专属集成验证不属于宿主状态记录。
