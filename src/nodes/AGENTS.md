# 宿主侧节点管理开发规范

继承 [源码模块规范](../AGENTS.md) 与 [项目规范](../../AGENTS.md)；职责见 [README](README.md)，部署与恢复见 [架构](../../docs/architecture.md)。

## 模块与外部节点边界

- 本目录只负责宿主侧身份、连接、能力路由、代理状态与执行事实核对；不实现或构建 Harness 提供方、日志采集等节点程序，不新增节点 Cargo 包或宿主节点启动角色。
- 具体节点由独立项目维护语言、依赖、平台后端、构建和发布；不得要求外部节点依赖整个 `recuvora` crate 或官方 SDK。
- 宿主根据已注册契约选择消费者；第三方宿主侧插件可增加带命名空间和版本的业务契约、schema、解释、流程和验证逻辑。宿主侧是逻辑职责，独立安装插件默认进程外，遵循 [插件设计](../../docs/plugins.md)。
- 缺失或不兼容插件只使相关能力不可用；节点声明、schema 和插件输出不能自行产生权限或权威执行事实。
- 当前已有可信 stdio/SSH 命令传输与外部注册/路由实现；节点程序仍由独立项目提供，测试子进程不能写成真实跨机器或业务支持。

## 身份与执行事实

- 重连核验节点归属、控制端身份、任务版本和授权；重新联网不自动恢复过期执行权。
- 要求外部节点在副作用发生前持久记录本地意图并检查执行上下文；宿主核对时保留原操作标识，不因重连派发新标识重做旧操作。
- 节点私有记录为权威业务恢复提供证据，不另建独立授权策略或第二套全局任务状态；身份、权限、限额与可信记录不能交由任意业务插件绕过。
- 远程目录和资源必须绑定所属节点，由实际执行端检查；宿主不得在本机文件系统中校验远程路径，也不得通过跳过范围检查实现远程接入。
- 区分节点心跳、能力可用性与目标健康；过期观测不得作为健康结论。
- 断线、取消和工作进程退出时保留 `Unknown`，先核验实际目标后再决定是否允许重试；不能统一转换为可重试失败。

## 外部节点义务与验证

- 将本机依赖、平台权限、目标检查、持久执行记录和进程监督作为外部节点接入义务，不把其实现并入本模块。
- 要求节点按信任、会话、资源与共同故障范围分组工作进程，报告能力实例关联；监督覆盖启动超时、输出上限、有限退避及子进程树回收。
- 释放资源前要求证据确认旧执行者不能继续操作；无法确认时保持相关任务阻塞并报告。
- 后台服务与交互会话由节点项目分别验证；宿主区分能力声明和已经验证的本机可用性。
- 宿主验证缺失能力插件、共享进程故障、长时间离线、日志容量耗尽、确认丢失与节点重启的协议处理；不以通信恢复代表任务恢复完成。
