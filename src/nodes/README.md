# 宿主侧节点与外部插件管理

本模块实现宿主侧外部扩展配置、注册、能力校验和调用路由。节点与宿主侧业务插件均为独立项目，Recuvora 不提供节点程序、发行包或节点构建角色。消息和配置见 [外部扩展协议](../../docs/extension-protocol.md)。

`ExtensionsConfig::load` 读取有界可信配置，校验程序、目录、命名空间及方法允许列表。`ExtensionRegistry::connect` 先探测并注册插件契约，再接入实现契约的节点。插件不能占用保留命名空间，节点不能自行定义宿主接受的新业务。单个扩展失效只停用相关实例，`statuses()` 给出原因；配置结构或命名空间冲突直接拒绝。每次调用重新握手，声明改变时要求重新注册。

CLI 和 HTTP 通过 [共享宿主](../boot/README.md#共享宿主装配) 将扩展注册表发布为框架服务。注册表直接使用 `framework::Cancellation` 与 `CallScope`；克隆句柄共享关闭状态。`begin_shutdown` 同步拒绝新调用并请求取消，`shutdown` 等待服务监督任务结束，调用者丢弃 future 不会提前释放在途所有权。排空不表示远端副作用已撤销，派发后的监督异常继续保留 Unknown。统一实现与自动验证边界见 [实现状态](../../docs/implementation-status.md)。

`call_read_only` 可以实际调用第三方插件/节点的新契约方法，校验输入和输出。插件可以通过 `service.call` 回调消费配置允许的节点只读服务；不允许通用接口调用保留契约、执行写操作或跨插件递归。元数据和 schema 不产生操作授权，插件结果不是权威业务事实。进程隔离不是权限沙箱，外部程序运行身份及文件访问仍由部署方限制。

可选监控专页复用同一注册机制，不增加可执行前端入口。插件需在 metadata capabilities 中标记 `recuvora.monitoring_view.v1`，并在自己的非保留命名空间内提供唯一、只读的 `describe_monitoring_view`；可信配置还必须把准确契约、版本和方法列入 `allow_calls`。缺一项或出现多个候选时仅把专属视图标为未登记/无效，不扩大调用权限，也不加载 HTML、脚本或原生代码。描述调用使用独立单槽并禁用节点回调，不占用普通业务/监控调用的四个槽；并发重复读取会关闭失败，不能拖垮采集容量。注册表同时记录每个版本化业务契约的 owning plugin，供服务器将业务 `owner_plugin_id` 与实际 provider `extension_id` 分开投影。

内置 `recuvora.harness` v1 经 [remote Harness 代理](../harnesses/remote.rs) 接入已有会话/项目/审批/工具服务。每实例共享 4 个普通调用槽和独立 2 个审批槽，实际 supervisor 收尾后释放。远端工作区以节点 ID 和工作区 ID 标识，由节点在资源所在机器检查真实目录；禁止在宿主把远端路径当本机路径校验。

正常响应、模型输出、节点声明、连接成功与目标健康是不同事实。断连、取消和未确认退出保留 Unknown，不能盲目重放。首版没有常驻节点心跳、安装市场、在线插件升级、自动恢复对账、通用远程执行许可或节点进程树监督；这些仍由后续实现及独立节点验收补齐。

当前验证使用集中集成测试的自身子进程，包括真实进程外插件注册、只读消费、缺失消费者、错误身份/版本/schema、回调关联及未知结果。未据此声明真实局域网部署、所有本机平台或长期稳定性支持。开发规则见 [AGENTS](AGENTS.md)。
