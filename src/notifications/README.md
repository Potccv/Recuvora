# 通知能力

本目录规划告警、待授权提醒和处理结果的投递插件，将权威业务服务已记录的事件发送到配置的渠道。

**当前状态：仅有目录与设计文档，尚无通知渠道或可运行插件。** 简单可信 Rust 渠道适配可内置并随宿主发布；复杂 SDK、第三方与独立安装扩展默认进程外。

## 职责与组织

- 本域组织通知服务契约、渠道提供方及投递消费者，按后端需要组织子模块；通过服务依赖和配置选择实现。
- 通知消费权威业务服务提供的事件视图，不自行判定修复成功、创建授权或改变恢复流程。
- 待授权消息仅作提醒；实际决定回到经过身份验证的授权入口，由权威业务服务确认与记录。
- 渠道失效只影响投递能力，权威任务事实与未受影响的插件继续按既定状态运行。
- 内置适配只选择已编入实现；独立扩展校验元数据、实例握手及能力注册。事件订阅、队列和连接属于实例，清理不能撤回已发送的通知。

## 输入、输出与权限

- 输入包含事件标识、任务版本、收件目标、消息模板和获准披露的摘要或证据引用。
- 输出包含投递标识、渠道确认、失败原因或送达状态未知；接口接受不等于最终收件人已阅读。
- 仅申请指定渠道、凭据和收件范围所需权限，不将模型生成的地址直接作为已获准通知目标。
- 敏感日志、截图和源码默认不随通知全文发送，实际披露内容由配置和数据权限约束。

## 失败与验证计划

- 投递失败、限流或渠道不可用不能回写任务为失败，也不能把已经完成的操作重新排队执行。
- 以事件、渠道和收件目标的稳定投递标识去重；回执丢失时按后端能力核验，并明确可能重复送达的限制。
- 实现后验证重复事件、超时、限流、乱序、进程重启、无效收件目标和发送后未收到回执的场景。
- 当前尚未选定渠道或送达保障，不承诺精确一次发送；队列、重试和保留期限均需在实现时限定。
