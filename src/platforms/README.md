# 平台交互插件

本目录组织桌面会话、画面采集、窗口定位和输入的宿主侧公共契约、消费逻辑与代理，并按操作系统维护外部节点接入约束。具体平台 API、采集与输入后端由独立节点项目实现和发布；专属新业务契约及消费者也可由第三方宿主侧插件提供。
当前仅有目录与设计文档，尚无平台契约代码、代理或节点接入实现，也无经验证的跨平台支持范围。

## 模块职责

- 通过统一能力契约报告当前会话、目标窗口、权限、可用后端与限制。
- 在有效任务授权和会话独占范围内向外部提供方派发采集与输入请求，消费其操作证据。
- 消费会话、显示配置、窗口身份和权限变化报告，要求提供方重新核验相关能力。
- 本模块维护通用平台契约与消费边界，具体平台能力由独立节点提供；目标专属流程、业务字段和资产留在对应集成项目中。

各平台目录维护宿主契约、代理及提供方接入要求，不收纳独立节点的原生后端实现。消费者依赖桌面服务，配置选择通过校验的外部提供方；宿主侧新契约与消费者可由独立安装、默认进程外的第三方插件扩展。
下述本机 API、权限、会话和资源要求由独立节点实施并提供验证结果。节点自行选择实现语言，负责桌面输入、采集及原生桥接的本机进程监督；可按用户会话与故障范围组合多个可信能力，不强制一能力一进程。
独立扩展经元数据校验、实例握手和能力注册接入；跨进程代理遵守共同契约并显式报告超时、断连及未知结果。具体系统 API 和后端尚待选择。
宿主事件订阅和能力绑定归属消费实例；节点的采集资源、原生回调与本机进程由节点管理。停用先停止新操作、处理在途请求，再按各自责任清理资源，effect 不会撤销已发生的外部动作；断线不能证明节点已回收资源。共同机制见[插件设计](../../docs/plugins.md)。

## 故障与验证

会话或目标身份变化后暂停相关输入并重新核验，不能将旧窗口标识继续用于新目标。
锁屏等状态对能力的影响须按后端验证；截图、输入和未受影响的监控分别报告可用性。
进程隔离不等于完整沙箱，需验证实际运行身份、系统权限与资源约束。
输入接口返回成功不等于目标业务接受操作；超时或回执丢失时先核验结果，不盲目重放。
后续验证需记录系统版本、CPU 架构、桌面环境、权限和后端，并覆盖取消、退出、会话变化及资源释放。
总体边界见[架构设计](../../docs/architecture.md)，本域开发要求见 [AGENTS.md](AGENTS.md)。
