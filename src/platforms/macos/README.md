# macOS 平台插件

本目录规划 macOS 用户会话、窗口、屏幕采集和输入的宿主侧契约、消费与代理，以及外部节点接入约束。具体 macOS API 与本机资源生命周期由独立节点实现和验证；专属新业务契约与消费者可由第三方宿主侧插件提供。
当前仅有设计文档，尚无本域契约或代理实现，也未验证桌面后端及 macOS 支持范围。

## 能力与边界

- 探测获准目标、当前交互会话以及截图和输入能力。
- 分别检查屏幕采集与辅助功能控制相关权限，报告能力限制。
- 在授权目标与会话独占范围内观察画面、发送输入并保留结果证据。
- 通过桌面服务契约与事件报告权限撤销、窗口变化和能力失效；进程代理保留断连与未知结果。

## 后端与部署设计

以下本机能力、部署和失败处理是外部提供方的接入要求，不表示本目录实现或发布 macOS 节点。

外部提供方自行选择实现语言，宿主配置按公共桌面契约绑定提供方；独立节点以受监督的会话进程隔离原生依赖，并自行管理本机进程。
声明所需服务，按实例登记能力、事件与采集资源；卸载清理不撤销已发生的外部输入，独立扩展先校验元数据与实例握手。
必要原生桥接单独封装和验证。
截图、窗口定位与输入的具体系统 API、支持版本和桥接依赖由节点项目选择并提交接入验证结果。
插件运行身份及用户会话必须与目标操作相匹配，不能把后台节点存活当作交互能力可用。
系统权限与任务授权分别校验：拥有屏幕或辅助功能权限不等于获准操作所有应用。
具体后端需记录系统版本、CPU 架构、应用身份、权限状态与实际后端。
目标专属规则、业务字段、资产及适配代码保留在对应集成项目中，Recuvora 插件通过正常发布更新。

## 失败与验证

权限撤销、目标窗口重建或会话切换后暂停相关输入，重新确认目标与所需能力。
锁屏、显示设备变化和应用状态对截图、输入的影响应按后端分别验证。
能力不足时向宿主提供明确原因与恢复条件，不能通过备用接口绕过未取得的权限。
操作回执缺失或超时后先核验目标状态，禁止直接重放可能已生效的输入。
后续验收覆盖权限拒绝与撤销、会话变化、显示缩放、多显示器及采集资源释放。
发布或更新后还应验证实际应用身份与权限行为；未验证前不承诺已有权限可直接复用。
独立进程不构成完整沙箱，所需权限与可落实的系统隔离边界必须实测并记录。
