# 跨边界协议开发规范

继承 [源码模块规范](../AGENTS.md) 与 [项目规范](../../AGENTS.md)；范围见 [README](README.md)，机制见 [插件设计](../../docs/plugins.md)。

## 语义与映射

- 协议只承载跨进程、跨节点表示与代理映射；业务服务契约由所属内置领域或第三方宿主侧插件提供，不强制本地服务序列化。
- 通用协议不得硬编码具体模型、日志等节点产品或穷举全部业务类型；外部节点按通用协议及所选能力契约接入，不要求依赖宿主 crate、Rust 或官方 SDK。
- 规划允许插件注册带命名空间与版本的业务契约、schema 和对应消费逻辑；命名空间归属、重复声明、兼容范围、依赖与限额必须可核验。宿主侧指逻辑职责，独立安装插件默认进程外。
- 业务扩展不能改变共同身份、权限、生命周期及结果状态语义，不能凭 schema、节点声明或插件输出产生授权与权威执行事实；遵循 [插件设计](../../docs/plugins.md)。
- 缺少插件或不兼容时只停用依赖它的能力；不能按未知格式执行，也不能由节点声明自动安装或信任插件。
- 为包、实例、工作进程、节点、任务、操作和调用分别定义身份，不以连接身份代替全部业务标识。
- 远程消息保留领域语义；变更同时说明契约来源、兼容范围、缺省行为与协商规则。
- 区分取消请求、取消确认、工作进程退出、报告结果与业务验证；保留无法确定副作用的状态。
- 明确时间单位、时钟含义、数值范围与消息上限，避免语言和平台解释不一致。
- 授权引用不是授权实现，调用端和实际执行端仍需校验任务、目标及有效范围。
- 远程资源标识绑定所属节点和作用域；通用协议不能把接收端本机路径解释当成远程范围校验。

## 验证与演进

- 先界定语义再选择传输与编码库；不凭当前示例声明正式协议版本或兼容保证。
- 变更同步受影响的领域或插件契约、外部节点接入约束、框架后端与可选 SDK，并维护一致的共享样本。
- 验证不兼容版本、错误身份、非法值、未知消息、重复及乱序回执，拒绝路径不可只依赖默认解码。
- 断连和超时不得统一转为可重试错误；涉及副作用的恢复保留 `Unknown`，由上层按原操作标识核验，不能自动重放。
- 验证缺失消费者、命名空间冲突、schema 限额、插件卸载中的在途调用及版本变更；独立插件失效不得丢弃宿主权威记录。
- 不将特定模型、目标类别或提供方内部结构固化为所有消息的通用前提。
- 当前已有 JSONL v1 与文档规定的严格 schema 子集；扩展生命周期为每调用一连接。修改消息、限制与 API 同步 docs/extension-protocol.md，不宣称完整 JSON Schema、自动重连或跨语言全面兼容。
