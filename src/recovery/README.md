# 自愈业务

本模块规划提供可信 Rust 业务服务与默认自愈流程，通过框架装配并随宿主共同编译发布。

**当前实现：[持久故障管理](#持久故障管理) 记录真实监控信号、来源检查点与人工确认；[最小模拟任务引擎](#模拟任务引擎) 提供封闭模拟；独立的 [审批存储](#审批存储) 提供人工或指定 Harness 的正式审批记录、精确操作绑定、单次执行意图与未知结果恢复；[文本修复流程](#文本修复流程) 将审批接入 Windows 本机受限文件动作。故障确认与模拟布尔授权都不能用于真实执行。完整自愈和目标专属外部动作仍未实现。**

官方控制台通过[统一 HTTP API](../../docs/console-api.md)调用这些服务。人工决定和执行带 revision 校验，actor 由服务端认证配置绑定。执行与审批选择独立节点工作区 ID，使模型上下文与宿主实际文件目标分离；宿主只通过通用 `remote-node` 接入 Harness 提供方。

## 职责

- 定义任务与故障、人工授权、权威恢复记录、调度和资源互斥的业务契约及可信实现。
- 持久记录任务版本、执行意图、报告结果与验证结果，支持中断恢复和事实核验。
- 提供默认的异常归并、诊断、授权、执行、验证与经验交付流程插件。
- 根据既有授权、环境与方案适用条件选择自动处理、等待人工授权或协助处理。

## 接口与边界

任务、授权、日志和调度是可装配服务，默认在可信宿主内运行；流程通过服务契约使用它们。配置可选择已编入宿主的实现，不能安装任意新业务代码。

授权和持久记录属于执行所需服务：初始化失败、依赖失效或提供者不明确时停止相关执行。替换关键服务必须排空在途任务并验证恢复记录，不允许形成两套权威状态。

[框架](../framework/README.md) 负责通用组合机制；[节点](../nodes/README.md) 汇报本地执行事实；监控、Harness、平台和知识领域分别提供能力。业务消费者不导入具体提供方内部实现。

已知方案也须匹配目标、环境版本和授权；未知方案可以在用户预先委托的明确范围内交给指定 Harness 评审。范围不匹配、评审失败或模型要求升级时等待人工处理；人工批准也不能覆盖可信配置的目标和动作限制。运行时修复 AI 只能修改获准目标，不能修改 Recuvora、插件包或启用配置。

## 持久故障管理

`crate::recovery::incidents` 是与模拟任务和执行授权分离的真实故障事实存储。监控引擎持有唯一 `Mutex<IncidentStore>`，来源采集和规则判断在锁外完成；查询、检查点提交和人工确认通过同一存储维护事实。`open` 接受项目源码之外的绝对日志文件路径，缺失父目录按需建立。公开接口和迁移位于 [incidents.rs](incidents.rs)，路径身份检查见[内部说明](incidents/README.md)。

- `commit(MonitorCommit)` 将一个 monitor 的完整检查点与按顺序排列的一批信号写入一条日志，`sync_data` 成功后才修改内存或确认游标。每个 monitor 从序号 1 开始严格加一；最新一批的完全相同重试不再落盘，旧序号或同序号不同内容拒绝。批内相同键按观察顺序处理，先故障再恢复不会丢失该次事件。
- 故障键为 `monitor_id + target_id + rule_id + kind`，`kind` 区分目标故障 `target` 与监控覆盖异常 `coverage`。`active` 创建或归并未解除事件，增加 `occurrences`；`unknown` 仅更新已有未解除事件且不会证明健康；`clear` 仅解除已有事件。覆盖异常由监控引擎显式提交 `active/coverage`，不能用目标未知代替覆盖事实。解除后的新故障创建新的 episode 与 ID，历史保留。
- `acknowledge` 比较当前 revision，只接受 `open` 事件，记录可信调用方提供的 actor、备注与时间，状态变为 `acknowledged`。确认不改变 condition，不执行修复，也不等于 `resolved`；后续可靠的 clear 信号才能解除。新的观察递增 revision，陈旧人工请求必须重读。actor 只是认证调用方绑定的审计归属，字符串本身不做认证。
- 记录包含 ID、revision、状态和条件、首次/最后观察时间、解除时间、确认信息、出现次数以及最新信号的 summary/evidence；完整信号顺序保留在日志。来源 ID、generation、cursor 和原始业务值由监控输入 evidence/检查点记录，不从命令退出码或 UI 状态推断健康。排序依据持久序号；系统墙钟回拨时记录时间取已有时间与输入时间的最大值，原始输入仍保留用于重放和精确重试比较。
- `get` 查询单条详情，`map_records` 在借用记录时投影列表摘要，避免复制全部 evidence。`close` 释放日志与目录句柄，保留只读内存视图并拒绝后续提交或确认；监控所有者必须先停止来源调用再关闭。

默认最多保留 10,000 个事件 episode、256 个 monitor 和 64 MiB 日志；可配置上限为 100,000、4,096 与 1 GiB。单条日志最多 512 KiB，单次最多 128 个信号，检查点最多 128 KiB，单个 evidence 最多 16 KiB。两者必须是 JSON 对象且嵌套深度不超过 32；summary 最多 2,048 UTF-8 字节，标识与 actor 最多 256 字节，确认备注最多 4,096 字节。容量不足拒绝整个提交，不推进任何检查点，不删除旧事件；此版没有日志压缩、轮转、迁移或自动历史清除。

日志采用格式版本 1 的 JSONL、全局严格递增序号和文件排他锁，实时与回放共用同一套迁移校验。完整记录损坏、未知格式、非法迁移或末尾残片均拒绝打开；写入、同步或文件身份检查失败后当前实例停止变更，内存仍保持最后确认的事实。失败返回不能证明磁盘未写入，重启必须先检查日志，禁止截断可能包含故障及检查点的尾部记录。路径拒绝符号链接、Windows reparse point 与日志硬链接，运行目录应限制为可信宿主身份可写。

自动测试在 [tests/incidents.rs](../../tests/incidents.rs) 与私有写入故障测试 [tests/incident_storage.rs](../../tests/incident_storage.rs)，覆盖重启、归并、原子检查点、批内转换、重放/重复冲突、Unknown、陈旧确认、容量、单写锁、关闭和墙钟回拨。它们不等于真实节点、跨机业务恢复、硬件断电或长期留存验收。监控故障解除只证明对应规则获得解除证据，尚未自动连接诊断、审批、执行或知识交付。

## 审批存储

`crate::recovery::approval` 是独立于模拟引擎的可信同步业务模块。`ApprovalStore` 只完成审批状态、执行意图和结果的持久化，不自行调用模型或执行工具。外部 Harness 调用由业务编排完成，不在存储状态变更期间等待网络或模型。

公开契约与操作入口位于 `approval.rs`；[私有实现](approval/README.md)按日志存储、状态迁移和路径校验拆分。实时请求与日志重放共用同一套迁移规则，拆分不改变日志格式、许可或授权语义。

- `ApprovalPolicy` 来自可信外部配置，包含策略 ID、版本、人工或指定 Harness 评审方式、委托说明、精确目标标签和动作种类白名单，以及 1 秒到 24 小时的有效期。
- `request` 由宿主生成请求 ID，记录任务及版本、操作 ID、目标、完整 JSON 动作和策略快照。同任务同操作 ID 的相同请求返回原记录；内容不同则拒绝。原批准不能随替换内容、目标或策略版本变化而复用。
- `assess` 只接受包含 `request_id`、`decision`、`reason` 的模型结果。Harness 实例与会话身份由宿主关联，存储验证指定评审者、状态、有效期与白名单后决定是否批准。模型字段本身不能构造执行许可。
- `decide_human` 是可信本地操作入口，记录宿主提供的操作人；该字符串仅用于归属记录，不是身份认证。`mark_waiting_human` 记录评审超时、格式错误或连接失败，不伪造模型判断。
- `consume` 比较完整操作及完整当前策略，核验有效期并阻断同目标 `Executing`、`Unknown` 记录，先同步保存 `Executing` 再返回不可构造、不可反序列化、不可克隆的 `ExecutionPermit`。执行端仍须复核真实文件和目标状态。
- `complete` 消费同一存储产生的许可，记录 `Executed`、`Failed` 或 `Unknown`。`revoke`、`cancel` 在执行前终止批准；执行中撤销或取消只能记录 `Unknown`，不会宣称已经回滚外部操作。
- `reconcile_unknown` 仅供可信操作人独立核验目标、确认旧执行者已经停止后记录终态。它永不恢复批准或重放原操作；后续操作必须使用新的操作 ID 和审批。

正常状态为 `Pending → Approved → Executing → Executed/Failed/Unknown`；模型拒绝进入 `Denied`，人工升级进入 `WaitingHuman`。人工或 AI 的批准不能越过硬范围限制；需要改变范围时由用户修改可信策略，并提交新请求。重复或迟到的评审、取消后的批准、过期消费、变化的操作与重复消费均拒绝。

运行目录必须为项目源码之外的绝对路径，拒绝目录祖先的符号链接或 Windows reparse point，日志和锁文件也拒绝链接及硬链接。部署机器不要求存在编译时源码目录；该目录存在时仍检查源码边界，其他解析错误拒绝打开。`approvals.lock` 使用 `fs2` 排他锁，`approvals.jsonl` 保存格式版本、严格递增序号、事件时间与完整审批事件；每次追加 `sync_data` 后才返回。默认保留最多 10,000 个审批请求和 32 MiB 日志，单条日志最多 256 KiB；无自动压缩、轮转或历史清除。完整或末尾残片损坏均拒绝打开，避免丢弃可能的执行意图后重新使用批准；写入或同步失败使当前存储永久停止变更。重启时先把 `Executing` 持久化为 `Unknown`，`Approved` 保留但不自动执行，未知目标继续阻断冲突动作。评审超时遇到有效期届满时先记录 `Expired`，不继续显示可以等待人工批准。

此存储依赖可信本地调用方、操作系统身份和运行目录权限；没有远程身份认证、签名审计、多宿主共识或对恶意同进程代码的隔离。文件同步不等于已验证所有文件系统或硬件断电场景。测试目标 `approval` 使用外部临时目录与可控时间，覆盖精确绑定、范围、人工升级、迟到评审、过期、撤销、单次消费、单写者、损坏、容量与中断恢复。

## 文本修复流程

`crate::recovery::workflow` 的 `RepairSession` 连接 Harness registry、审批存储与 `actions::ScopedFiles`，通过独立 `repair` CLI 使用。执行 Harness 提议白名单文件的准确全文替换；审批可以选择同一实例，但始终使用新的 Hidden 无工具会话和独立审批容量。流程在模型调用期间不持有审批存储锁，评审失败、拒绝或升级会阻止本轮继续派发。

`run` 返回 `RepairResult`、`RepairStatus` 和实际 Harness 错误等类型化事实，不调用界面代码。CLI 与 HTTP 在 `interfaces::repair` 中共用 JSON 表达，保留错误关联信息、Unknown、禁止自动重试及业务未验证的语义。

真实动作记录原始用户请求、执行会话、实际目标根、完整原文和替换内容。执行前重新核验政策、有效期、文件身份及原文，再消费一次许可；写入或回执不确定保留 `Unknown`。人工批准只保存决定，必须显式 `apply`；`reconcile` 只读取目标现状并记录核验结果，不重做写入。相同实际根的未知操作不能通过修改目标标签绕过。

当前仅支持 Windows 既有 UTF-8 普通文件，具体文件边界与同账号进程限制见 [动作模块](../actions/README.md)。流程只验证文件读回，输出 `business_verified=false`；没有业务健康验证、任意命令执行或自动续接。配置、人工接管、退出码和恢复方式见 [审批使用说明](../../docs/approval.md)，测试集中在 `tests/workflow.rs`。

## 已有原型与后续验证

`crate::recovery` 的封闭模拟覆盖诊断、执行和验证阶段，支持同目标互斥、跨目标并发、重复 ID、取消、超时、失败和模拟回执丢失。原型 JSONL 日志在确认前同步落盘，进程重启后执行中任务保留 `Unknown`，不自动重放。实现与限制见 [引擎说明](#模拟任务引擎)，测试入口与验收范围见 [测试目录](../../tests/README.md)。

以下仍属于后续真实业务验证：

- 扩展到目标专属平台时，继续验证必需服务缺失、外部操作边界与同目标争用；当前审批存储已有重复、过期、撤销和未知目标阻断测试。
- 在持久化与外部动作间中断，核验未知结果不被盲目重放；知识交付失败不重做已完成修复。
- 验证关键服务替换、宿主重启、磁盘不足与长期队列增长，确认恢复前重新检查授权和资源。

生产数据库、迁移方式和真实流程 API 尚待选定；现有原型格式不承诺生产兼容，也不承诺外部操作精确一次。共同设计见 [架构](../../docs/architecture.md)，本域规范见 [AGENTS.md](AGENTS.md)。

## 模拟任务引擎

`crate::recovery` 是随宿主发布的可信 Rust 内置模块，验证调度、任务状态和中断恢复。它只接受封闭的 `Simulation` 输入，不调用 Harness、命令、文件修复或真实平台，也不提供任意执行器入口。

### 接口与运行

- `Engine::open(data_dir, EngineConfig)` 打开外部运行目录，取得独占写锁，核验日志并恢复任务。
- `Engine::handle()` 返回可克隆的 `EngineHandle` 服务契约，提供提交、查询与取消；引擎所有者单独负责关闭。
- `submit(TaskSpec)` 在落盘后确认接收；相同 ID 和内容返回原记录，相同 ID 的不同内容拒绝。
- `query(id)` 读取最近已持久化状态；`cancel(id)` 请求取消并等待模拟任务退出及终态落盘。
- `shutdown()` 关闭新派发，取消并回收模拟任务，持久化停止状态。丢弃引擎会中止 actor 和模拟任务；下一次打开保守恢复。

配置为并发上限 `max_concurrency`、等待队列上限 `max_queued`、包含历史记录的任务总数上限 `max_tasks` 和日志字节上限 `max_journal_bytes`。达到限制返回结构化错误；此版不删除历史、不轮转日志。运行目录必须在源码目录之外。

目标互斥由调度器统一分配；同一目标的等待任务不会占用执行槽，也不会挡住其他目标。任务通道、接收队列、并发、历史条数、文本与超时均有上限。时间上限从派发开始计算，不包含排队时间。

### 状态与授权

正常路径为 `Queued → Diagnosing → Executing → Verifying → Succeeded`。未调用 `authorize_simulation()` 的输入落盘为 `Denied`；该方法仅允许本模块内固定无副作用模拟，**不是用户身份核验或真实执行授权**。

`Simulation` 支持成功、报告失败、验证失败、执行延迟、永久等待及模拟执行者失联。报告失败为 `Failed`；执行期间取消、超时和模拟失联为 `Unknown`，因为执行回执不确定时不能宣称操作没有发生。执行开始前取消或超时分别为 `Canceled`、`TimedOut`。单任务失败不会终止其他目标任务。`Unknown` 是需后续核验的停止状态，本版本没有自动重试或人工消歧接口。

重启时 `Queued`、`Diagnosing` 转为 `Canceled`，`Executing`、`Verifying` 转为 `Unknown`，并在开放提交前落盘；全部保留原 ID，不自动重放。模拟取消会等待 Tokio 任务回收再返回终态。`Unknown` 会持续阻断该目标的新任务，重启后仍保留阻断；其他目标不受影响。本版没有核验解除接口，需后续真实授权与核验服务才能恢复未知目标。

### 持久记录与边界

原型 `tasks.jsonl` 使用版本化完整任务快照，记录全局顺序与任务修订号，每次追加都 `sync_all` 后确认。`writer.lock` 在运行期间排他锁定。完整记录损坏、未知版本、非法状态迁移、容量超限或写锁已被占用均拒绝打开。只有缺少末尾换行的未确认残片可截断。写入失败停止 actor 和模拟任务，新请求返回不可用；重启必须先解决存储故障。

此格式仅供原型验证，无迁移、压缩、灾难备份或生产级审计承诺。同步文件内容不等于所有文件系统与断电场景均已验证；测试覆盖进程被终止，不能据此承诺硬件断电可靠性。同进程 Rust 模块共享宿主故障边界；本模块未实现第三方插件进程监督或权限沙箱。

测试目标登记为 `recovery`；[集中测试目录](../../tests/README.md) 维护执行方式与通过范围。具体宿主组合由 boot 选择；本模块不依赖框架内部实现。新增模拟类型需更新宿主，不支持热安装。
