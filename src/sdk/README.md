# 插件与节点开发辅助

本能力组规划提供可选的插件与外部节点开发辅助，复用框架公开接口、业务契约与跨边界协议。Recuvora 不提供具体节点程序；节点由独立项目构建和发布，接入不要求使用 Rust、依赖整个 `recuvora` crate 或使用官方 SDK。

**当前状态：本能力组仅有设计文档，尚无独立 SDK 包或多语言便利封装。** 宿主已提供 [JSONL v1 扩展协议](../../docs/extension-protocol.md)，第三方进程可据此注册契约、调用获准方法及消费只读能力，不需要等待 SDK。框架内部 Rust API 不构成稳定 SDK 承诺。

## 职责

- 为可信本地模块提供服务声明、依赖访问、事件与资源生命周期的开发入口。
- 为进程外插件与外部节点提供可选的握手、注册、调用关联、错误、取消与连接失效封装。
- 为已有的带命名空间和版本的契约/schema 注册及只读消费协议提供便利封装；通用流程与业务验证辅助仍待实现。
- 帮助开发者表达配置、能力限制、运行边界和执行证据，减少重复接入代码。
- 维护具体语言接口与框架、领域契约及 wire 协议之间的兼容说明。

## 依赖与边界

本地接口以 [框架](../framework/README.md) 和公开业务契约为来源；远程接口以 [协议](../protocol/README.md) 及内置领域或插件声明的能力契约为来源。SDK 不创建另一套服务容器、授权规则或权威任务状态；schema 校验和能力声明不产生授权。

本地注册助手仅面向随宿主共同编译发布的可信代码，不提供任意代码安装能力。第三方宿主侧插件可通过已有 JSONL v1 接口提供新业务契约和只读消费逻辑；宿主侧指逻辑职责，独立安装插件默认进程外，不代表原生动态库加载。外部节点与插件均可自行选择实现语言；SDK 支持语言、绑定与分发方式待实际需求确定。

便利封装应显式保留目标、作用域、截止时间和未知结果，不能默认重试可能产生副作用的请求。资源释放也不能声称撤销已经发生的外部动作。

符合正式协议与能力契约的独立实现应可接入，宿主和执行端仍须分别完成其权限校验。节点项目自行负责本机平台依赖、进程监督、目标检查与必要执行记录；SDK 不能将这些义务隐含交给宿主。缺失或不兼容的业务插件只使相关能力不可用，便利封装不得隐式选择替代消费者或放宽契约。

## 计划验证

- 验证本地服务声明、依赖与清理行为同框架一致，不形成第二套生命周期。
- 用共享样本核验远程握手、错误、取消、实例失效及领域语义在各语言间一致。
- 验证不使用官方 SDK 的实现能够按相同协议接入，以及缺失能力插件、命名空间冲突与不兼容版本的明确拒绝。
- 验证关闭时资源释放、待处理调用有明确状态，超时和重连不会隐式重复动作。

接口名称、多语言绑定和分发方式尚待实现确定。共同规则见 [插件设计](../../docs/plugins.md)，本域规范见 [AGENTS.md](AGENTS.md)。
