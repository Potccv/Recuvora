# 测试开发规范

继承 [项目规范](../AGENTS.md)。范围见 [README](README.md)，验收依据为 [架构](../docs/architecture.md) 与 [插件设计](../docs/plugins.md)。

- 全部测试代码维护在本目录，按模块与场景组织；由项目根单一 Cargo 包显式登记集成测试目标，辅助文件不单独成为测试或产品入口。
- 进程故障夹具作为集成测试子进程运行，不增加独立 Cargo 包或产品故障注入二进制。夹具入口默认忽略，缺少专用模式环境变量时不得执行故障动作；父测试必须设置等待上限并回收子进程。
- 验证可观察业务不变量与生命周期，不编写仅重复实现细节的断言。
- 框架测试覆盖本地服务与依赖、注册清理；远程代理额外覆盖握手、乱序、迟到回复和失联，不混淆两类边界。
- 故障注入明确位于持久化、派发、副作用或确认的哪一阶段，检查恢复后的目标状态。
- 检查授权和日志服务缺失时执行是否停止，流程替换是否仍经过强制授权检查。
- 取消、卸载和重启检查残留子进程、锁及重复动作；effect 清理成功不算外部回滚成功。
- 使用可控时钟或显式事件，避免依赖任意睡眠与运行顺序。
- 使用隔离临时目标和脱敏素材；所有测试临时文件写入执行环境指定、且位于项目根之外的统一临时目录，不得在本目录或项目内另建临时输出目录。
- 测试通过后立即清除不再需要的本次临时文件。失败时仅保留排查所必需的文件，排查结束后及时清除；自动清理只处理本场景创建并记录的资源。
- 外部服务和交互会话场景显式声明环境与副作用前提，不默认操作当前活动目标。
- 测试说明和夹具文档只使用中立目标、工作负载、提供方观测和外部动作，不记录具体产品、实例、业务字段、真实故障内容、活动部署或跨项目验收历史。
- 长期验证报告时长、负载、资源变化与退出恢复，模拟结果及短运行不能替代平台和稳定性验收。
- 测试入口存在后才记录运行命令；文档改动只做对应的路径、链接和内容检查，报告未运行项。
